Sargantana: FP decoder ISA-compliance audit

bsc-loca/sargantana · SystemVerilog · 64-bit in-order RISC-V core (BSC)
6 issues raised · fixes + regression tests in progress

While preparing for the hardware-enforced CFI mentorship on this core, I read the instruction decoder against the spec, looking for encodings that should raise an illegal-instruction trap but don't. Almost every bug sits in two fields of the OP-FP encoding. Hover an issue to see which field it hits.

Quad-precision accepted instead of trapping. Decoder handles S/D/H, but the default case clears the illegal-instruction exception.

The reciprocal conversion path lacks the same selector validation.

05FMV.X.* / FCLASS.*

Accept non-zero rs2 even though the field is reserved.

06FMV.*.X

Accepts any rs2. Only 0 (FMV) and 1 (Zfa FLI) are legal.

riscv-arch-test: trap & exception correctness

riscv/riscv-arch-test · official architectural compliance suite
2 merged

Two bugs where the test framework itself corrupted architectural state during exception handling. A compliance suite can't afford that class of bug.

MERGED · fixes #1727

failedtest_saveresults_int took a secondary trap that overwrote the original mcause. The fix bounds-checks the expected-value pointer against rvtest_sig_begin/_end.

MERGED · fixes #1753

ExceptionsS aborted on a misaligned load/store exception. Root causes: a redundant sp adjustment in the trap handler and a TRAP_SIGUPD_COUNT overflow.

ZeroKV

Rust · libibverbs · RDMA / RoCE · repo ↗
How fast can a GET be if the server never wakes up?

A key-value store whose read path bypasses both the kernel and the server CPU. Clients issue one-sided RDMA READs straight into the server's registered memory, and the NIC does the copy. Writes use the HERD pattern: an RDMA-WRITE into a per-core message buffer, picked up by spinning poller threads.

4 µsp50 GET (Redis 7)
88×lower max latency
126Kops/s · 8 threads · 0 mismatches
0.10 µsp50 cached, Zipf-1.2
  • Cuckoo hash + seqlock slots: 64-byte slots with a split version word. Torn reads are detected and retried without locks (18 of 800K, all recovered).
  • One QP/CQ/MR per thread: RC QPs aren't thread-safe, and with a shared CQ one thread can steal another's completion.
  • Async batching up to 32 deep, with an auto-drain every 64 unsignaled WRs to prevent silent SQ overflow.
  • Debugged GID-index mismatches, 128-byte MsgSlot alignment and SoftRoCE routing.

Sentinel-X

C (eBPF/XDP) · Python · Next.js · repo ↗
Drop the packet before the kernel pays for it.

DDoS mitigation at the XDP hook, before any sk_buff is allocated. The fast path does an LPM-trie blacklist lookup and a per-IP rate-limit lookup. An asynchronous control plane reads a BPF ring buffer and runs XGBoost + Isolation Forest (trained on CICIDS2017) to rewrite the rules live, so the kernel program never blocks.

96.51%drop accuracy
0.31%false positives
0.066 msp99 verdict under flood
5.2 MBall kernel maps
  • Per-CPU arrays for lockless telemetry: no atomics and no shared cache lines on the hot path.
  • Ring buffer instead of perf-event array: FIFO ordering and one shared buffer instead of N per-CPU buffers.
  • Verifier-safe bounded parsing. Validated on veth namespaces, which cap the testbed at about 2–3 Mpps.

Onitro

C++ · AVX2 · OpenMP · CMake · group project
A vectorised Monte Carlo derivatives pricing engine.

I own the fixed-income pricing module and a Monte Carlo engine for European and Asian options.

  • Variance reduction with antithetic and control variates.
  • Per-option PCG32 RNG streams for reproducible, parallel-safe sampling.
  • Paths are processed in chunks behind an ONITRO_SIMD macro, with SIMD expansion controlled from CMake rather than raw #pragma omp simd.
  • All SIMD lives in one dedicated header, so the pricing maths stays readable and testable on its own.
